# DriveMate V8 前端设计规范

> 技术栈：Streamlit + `api_client.py`
> 版本：4.1
> 状态：2026-09-03 当前实现基线
> 对齐范围：`app.py`、`views/*.py`、`ui_chrome.py`、`assets/figma-hmi/styles/*.css`

## 1. 视觉方向

DriveMate 是车载三屏工作台，不是通用后台。桌面从左到右依次回答：

1. 驾驶舱：车辆现在怎样；
2. 智能中控：任务、证据和执行状态怎样；
3. DriveMate：用户可以发起什么、需要确认什么。

中控固定为六个业务页签：路线导航、座舱控制、安全评估、融合感知、服务编排和指令记录。六页签与“感知—理解—裁决—规划—执行—回读—输出”七阶段编排是两套不同结构，不得混称。

整体使用车载光学玻璃，并提供日间、夜间两套主题。道路实景是环境锚点，Safety Halo 是唯一强视觉签名；其他组件依靠排版、间距和语义色建立层级，不增加无信息装饰。

## 2. 响应式栅格

### 2.1 完整桌面：`≥ 1200px`

| 项目 | 规范 |
|---|---|
| 页面外边距 | 12px |
| 顶部系统栏 | 48px |
| 系统栏与主区间距 | 12px |
| 三栏比例 | `30 / 45 / 25` |
| 三栏间距 | 12px |
| 主区高度 | `calc(100dvh - 84px)` |
| 主面板滚动 | 驾驶舱、中控独立滚动；助手仅消息区滚动 |

三列必须同高、同顶线、同底线。内容少的页面不拉伸内部卡片填空；内容多的页面通过所属主面板局部滚动，不裁切、不把整个浏览器页面推高。

### 2.2 紧凑桌面：`1200–1280px`

- 保持三栏比例、固定视口和全部业务功能；
- 仅隐藏品牌副标题，连接状态、API 版本、工具数和时间保持可见；
- 仅压缩次要信息，不隐藏页签、状态、操作或证据。

### 2.3 中屏与平板：`≤ 1199px`

- 顶部系统栏改为品牌/模式、状态/主题的 2×2 卡片栅格；
- 驾驶舱、中控、助手改为纵向排列；
- 页面恢复浏览器纵向滚动；
- 主面板高度由内容决定，不保留桌面固定视口高度。

### 2.4 组件断点

| 断点 | 行为 |
|---|---|
| `≤ 760px` | 融合决策、安全态势、证据栅格改为单列；页面状态移到标题下方 |
| `≤ 560px` | 顶栏单列；仪表、车控、记忆、指标、模态输入和等待阶段单列；路线端点纵排；中控页签三列 |
| `≤ 420px` | 中控页签两列；助手快捷操作单列 |

移动端保留全部业务信息、按钮、状态和证据，不通过隐藏内容解决空间不足。系统同时响应 `prefers-reduced-motion`，关闭非必要动画和过渡。

## 3. 间距系统

只使用以下布局间距：

| 令牌 | 数值 | 用途 |
|---|---:|---|
| `--space-1` | 4px | 标签、图标与文字、紧密元素 |
| `--space-2` | 8px | 同组元素、信息单元内边距 |
| `--space-3` | 12px | 卡片内边距、主栅格间距 |
| `--space-4` | 16px | 主要内容分区、宽松卡片 |
| `--space-6` | 24px | 空态或唯一强调区 |

相同关系必须使用相同令牌。页面、栅格与卡片的布局关系使用 `gap`，不以逐元素 margin 拼接。非令牌数值只用于边框、图标、控件固定几何或光学对齐，不得参与页面级布局。

## 4. 字体层级

全局字体：`"Microsoft YaHei UI", "Microsoft YaHei", sans-serif`。

| 角色 | 令牌 | 字号 | 建议字重 |
|---|---|---:|---:|
| 标签 / 眉标 | `--type-label` | 10px | 700–750 |
| 辅助说明 | `--type-note` | 11px | 400–650 |
| 正文 / 控件 | `--type-body` | 12px | 400–650 |
| 模块标题 | `--type-section` | 14px | 700–750 |
| 页面标题 | `--type-page` | 18px | 750 |
| 主面板标题 | `--type-panel` | 20px | 750 |
| 大数值 | `--type-value` | 24px | 600–700 |
| Safety Halo | `--type-halo` | 32px | 700 |

字号不足时先改变栅格，不使用小于 10px 的文字。说明、结论和证据允许换行；只有稳定短标签可以单行省略。纯符号图标按组件几何定尺寸，不视为文字层级。

## 5. 圆角

| 层级 | 令牌 | 数值 |
|---|---|---:|
| 主面板 | `--radius-panel` | 20px |
| 功能卡 | `--radius-card` | 14px |
| 信息单元 / 输入 / 按钮 | `--radius-unit` | 10px |
| 状态胶囊 | `--radius-pill` | 999px |

## 6. 三层玻璃

所有玻璃容器统一使用 `12px` 高斯模糊，通过表面、边界和阴影区分层级。日间主题使用透明白，夜间主题改用深蓝表面，不机械复用日间透明度。

| 层级 | 日间表面 | 夜间表面 | 用途 |
|---|---|---|---|
| L1 主面板 | `rgba(255,255,255,.22)` | `rgba(14,24,40,.58)` | 顶栏、驾驶舱、中控、助手 |
| L2 功能卡 | `rgba(255,255,255,.15)` | `rgba(20,34,54,.50)` | 页面头、地图、控制卡、证据卡、输入区 |
| L3 信息单元 | `rgba(255,255,255,.09)` | `rgba(26,44,70,.52)` | 指标、标签组、状态摘要、消息气泡 |

主题基础色：

| 主题 | 背景 | 正文 | 辅助文字 | 强调色 |
|---|---|---|---|---|
| 日间 | `#f2f8fc` | `#203047` | `#66768b` | `#4778f5` |
| 夜间 | `#101826` | `#eef5ff` | `#9aabc2` | `#7fb2ff` |

成功、提醒、高风险和紧急风险分别使用 `#1f8a68`、`#a96812`、`#c7653d`、`#c83f54`。语义色只作用于状态、数字、进度和局部边界，不改变整张卡的材质。

## 7. 共用组件

| 组件 | 责任 |
|---|---|
| `dm-panel-header` | 驾驶舱与智能中控统一眉标、20px 标题和状态 |
| `dm-chat-title` | 助手栏紧凑标题，与在线状态组成 46px 头部 |
| `dm-page-header` | 六个中控页统一 18px 标题、说明和状态 |
| `dm-card` | L2 功能卡 |
| `dm-unit` | L3 信息单元 |
| `dm-metric-grid` | 同级大数值摘要 |
| `dm-evidence-grid` | 风险、策略、验证、方案和回执 |
| `dm-status` | 在线、运行和风险状态 |

页面专属 class 只定义该页面的布局与语义，不重复定义基础材质、字号、圆角和间距。

### 7.1 顶栏与导航

- 顶栏桌面顺序固定为品牌、出行模式、后端状态、日夜主题，列权重为 `1.1 / 1.3 / 0.82 / 0.48`；
- 出行模式仅有“车主自驾”和“Robotaxi 乘客”；模型选择不占顶栏，位于助手输入区的弹出选择器；
- 后端状态区显示 Mock/连接状态，并补充 API 版本、工具数量和本地时间；
- 中控六页签桌面单行六列，`≤560px` 三列，`≤420px` 两列；
- `topbar-marker`、`left-pane-marker`、`center-pane-marker`、`right-pane-marker` 等隐藏标记只用于约束 Streamlit 生成的容器，不承担可见内容。

## 8. 页面规则

### 驾驶舱

- 结构固定为标题、16:9 道路实景、四项仪表、座舱同步和可选订单卡；
- 四项仪表共享标签起点、24px 数值比例和最小内容高度；
- 车主模式的仪表为 2×2；Robotaxi 桌面态压缩为单行四项并追加订单卡；
- 道路图片保持静态，不推测车辆位置；车速、里程、驾驶时长、电量和续航可由本地演示计时器更新；
- Robotaxi 订单增加内容时允许左栏滚动，不裁切订单事实。

### 导航

- 页面头后以单一任务卡承载端点关系、三项行程指标、推荐路线和地图；
- 默认“上海虹桥火车站 → 上海外滩”使用确定性的演示路线、42 分钟、22.4 km 和静安寺推荐点，并明确标注工具回传优先；
- 非默认目的地仅在本轮 `navigation` 与目的地一致时显示已更新，否则展示待规划；
- 地图弹性占据任务卡剩余高度；手机端使用 `168px` 最小高度和 `1.65:1` 比例；
- 地图可动画展示路线流向，但不得动画推测车辆位置；当前页面不提供独立路线表单，目的地变更通过 Agent 与 `state_diff` 完成。

### 车控

- 温度、座椅、车窗、氛围灯共享同一控制卡骨架；
- 桌面 2×2，手机单列；
- 滑杆只更新本地预览；
- “交给 DriveMate 评估并执行”是唯一主动作。

### 融合感知

- 四路输入为 2×2，手机单列；
- 顺序为输入、处理链、置信度演进与融合核心、全宽行动结果、融合判断；
- 行动结果和融合判断必须完整换行，不以省略号隐藏关键证据；
- 无 Run 时可根据当前快照展示待命态；有 Run 时优先消费后端 `perception_fusion` 和 `action_outcome`；
- Mock 输入明确标注“演示数据 · Mock Sensor Bus”，完整原始结构通过“查看本次融合证据”弹出区展示。

### 服务编排

- 页面区分待命、已提交/等待 Agent、已有 Run 三种状态；
- 待命态由一句行动提示和七阶段组成，容器由内容决定高度；
- 等待态只展示请求已进入流程的扫描反馈，不伪造具体阶段完成；
- Run 态展示当前阶段、阶段证据、编排方案、工具回执和审计下载；
- 方案与回执共享同一证据栅格；
- 阶段只来自 `phases` 或已有字段，不伪造实时进度。

### 安全守护

- Safety Halo 是唯一焦点；
- 优先显示后端 `safety_score`；缺失时显示原始 `L0–L3`，不得前端推算评分；
- 场景与执行进度是 L3 辅助单元，进度只统计七阶段中状态为 `done` 的证据；
- 风险判断完整换行；
- 风险依据、策略约束和验证证据使用自适应证据栅格，每类先展示两项，其余引导至服务编排；
- 首次收到 `L3` 或 `critical` 运行结果时自动切换到安全守护并显示一次提醒。

### 指令记录

- 仅展示当前页面与当前会话事实；
- 当前上下文使用 2×2 L3 信息单元；
- 车主与 Robotaxi 使用各自四项上下文；
- 最近请求最多显示四条并按最新优先排列，空态不扩大容器；
- 不把本次会话事实表述为长期记忆或长期用户偏好。

### DriveMate 助手

- 快捷操作桌面为三列两行，按车主/Robotaxi 模式切换，`≤420px` 单列；
- 消息区弹性占据剩余高度并独立滚动；
- 历史对话按模式过滤，最多呈现最近六条历史消息；当前 Run 回复单独保持可见；
- 用户消息居右、Agent 消息居左，使用各自头像；
- 输入表单自然位于面板末端，依次提供文本输入、模型选择、语音按钮和发送按钮；
- 模型选择支持“融合编排 · 可审计”和“百炼应用 · App API”；
- 浏览器支持时，中文语音识别填入输入框，Agent 新回复自动语音播报；不支持时禁用语音按钮并保留文字输入；
- 确认、取消及执行反馈跟随当前 Run；执行反馈优先展示最多六项 `state_diff`，否则展示最多四项已完成步骤。

## 9. 状态与数据边界

- 所有页面共享 `current_run`、`pending_request`、`request_state`、`messages` 与座舱预览状态；
- 切换出行模式会清空当前 Run、待处理请求和本轮结果，重置导航页、行程里程及模式目标车速；历史消息保留但按模式隔离展示；
- 快捷操作、文本发送和车控提交均先写入 `pending_request`，随后自动切换到服务编排；
- 确认或取消只有在对应 API 成功返回后才能更新运行状态；确认前不得显示已完成；
- `state_diff` 成功返回后同步到温度、风量、座椅、车窗、氛围灯、媒体、导航目的地和车辆位置等本地预览；
- 感知证据、阶段、编排、工具回执与审计只在对应页面展示；风险证据统一归入安全守护；
- 前端只通过 `api_client.py` 调用后端，不导入后端实现、数据库、规则引擎或私有推理；
- `app.py` 只负责页面组装、会话状态与事件编排；`views/` 通过显式上下文接收渲染所需状态、客户端与回调，不反向导入 `app.py`；
- 合同错误、请求失败和后端未连接必须显式展示，不以成功形态的默认值掩盖。

## 10. 可访问性与动效

- 主操作必须有可见的键盘焦点；状态不能只依赖颜色，须同时提供文字；
- 场景、仪表、地图、进度和语音入口保留语义标签；
- 关键信息允许换行，省略号仅用于稳定短标签或紧凑回执标签；
- 路线流向、等待扫描和数值演示属于非关键动效；系统请求减少动态效果时必须停用；
- 静态道路图和路线图不得制造实时车辆定位、真实执行或已完成的错觉。

## 11. 验收

1. `1280×720`、`1366×768` 下顶栏为 48px，主区为 `calc(100dvh - 84px)`，三栏同顶同底且比例为 `30 / 45 / 25`；
2. 中控仅有六个页签，桌面单行六列；七阶段只出现在服务编排和安全进度；
3. 六个中控页面标题区的内容起点、圆角和间距一致；
4. 驾驶舱与中控真实超出时可局部滚动，助手仅消息区滚动，输入区稳定贴近底部；
5. `1199px` 以下主布局纵向排列，`760 / 560 / 420px` 组件断点生效；
6. 日间与夜间主题均保持三层材质、文字对比和语义色含义，全部玻璃模糊为 12px；
7. 所有页面无横向溢出，关键说明、风险结论、行动结果和证据不被裁切；
8. 页面级间距与全部文字角色使用设计令牌，非令牌数值仅限图标、控件几何与光学细节；
9. 默认导航演示与后端回传有清晰边界，未返回的执行、回读和路线不得伪装为实时完成；
10. 模式切换、主题切换、滑杆、快捷操作、发送、确认、取消、语音、审计下载和 `state_diff` 联动保持可用。
